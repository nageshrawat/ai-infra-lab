## What is Terraform?

Terraform is an Infrastructure as Code (IaC) tool that allows infrastructure to be defined and managed using code.

Instead of manually creating resources:

```text
Create VM
Create Network
Create Database
```

You define infrastructure in code:

```hcl
resource "aws_instance" "web" {
  ...
}
```

Terraform creates and manages it.

---

## Terraform Workflow

```text
Write Configuration
        ↓
terraform init
        ↓
terraform plan
        ↓
terraform apply
        ↓
terraform destroy
```

---

## Terraform Commands

### 1. terraform init

Purpose:

- Initializes Terraform project
- Downloads providers
- Creates `.terraform` directory
- Creates `.terraform.lock.hcl`

Command:

```powershell
terraform init
```

---

### 2. terraform plan

Purpose:

- Compares desired state with current state
- Shows what Terraform will do

Command:

```powershell
terraform plan
```

Example Output:

```text
Plan: 1 to add, 0 to change, 0 to destroy.
```

---

### 3. terraform apply

Purpose:

- Creates or updates infrastructure

Command:

```powershell
terraform apply
```

---

### 4. terraform destroy

Purpose:

- Removes resources managed by Terraform

Command:

```powershell
terraform destroy
```

# Terraform State

## terraform.tfstate

Stores:

- Resource information
- Resource IDs
- Current infrastructure state
- Resource attributes

Purpose:

```text
Current State
      vs
Desired State
```

Terraform uses the state file to determine required changes.

---

## terraform.tfstate.backup

Stores backup of previous state.

Used for recovery if state changes unexpectedly.

---

# Terraform Lock File

## .terraform.lock.hcl

Purpose:

- Locks provider versions
- Ensures consistent environments

Example:

```text
hashicorp/local v2.9.0
```

Similar to:

```text
requirements.txt
package-lock.json
```

---

# Terraform Variables

Created reusable variables.

## variables.tf

```hcl
variable "app_name" {
  default = "Infra API"
}

variable "environment" {
  default = "dev"
}

variable "port" {
  default = "8000"
}
```

Benefits:

- Avoid hardcoding values
- Reuse infrastructure code

---

# Terraform Outputs

Created outputs.

## outputs.tf

```hcl
output "config_file_name" {
  value = local_file.app_config.filename
}

output "environment" {
  value = var.environment
}

output "port_no" {
  value = var.port
}
```

Output:

```text
config_file_name = "app.conf"
environment = "production"
port_no = "8080"
```

---

# terraform.tfvars

Created environment-specific values.

## terraform.tfvars

```hcl
app_name    = "Incident API"
environment = "production"
port        = "8080"
```

Purpose:

Separate:

```text
Code
   from
Configuration
```

Used in real projects:

```text
dev.tfvars
qa.tfvars
stage.tfvars
prod.tfvars
```

# Terraform Lab 2

## Create Configuration File

### main.tf

```hcl
resource "local_file" "app_config" {
  filename = "app.conf"

  content = <<EOF
APP_NAME=${var.app_name}
ENV=${var.environment}
PORT=${var.port}
EOF
}
```

Generated:

```text
APP_NAME=Incident API
ENV=production
PORT=8080
```

# Terraform Change Detection

Original:

```text
APP_NAME=Infra API
ENV=dev
PORT=8000
```

Updated:

```text
APP_NAME=Incident API
ENV=production
PORT=8080
```

Terraform detected:

```text
Desired State != Current State
```

Generated:

```text
1 to add
1 to destroy
```

Applied changes automatically.
