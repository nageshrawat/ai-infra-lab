# Day 7 – AWS Networking & EC2 with Terraform

## Objective

Learn AWS networking fundamentals and provision infrastructure using Terraform.

---

## Topics Covered

### 1. VPC (Virtual Private Cloud)

Created a custom VPC:

```hcl
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
}
```

### Learnings

* VPC is a logically isolated network in AWS.
* CIDR `10.0.0.0/16` provides 65,536 IP addresses.
* Terraform state stores created resource information.
* Resource IDs should be referenced instead of hardcoding values.

---

### 2. Subnet

Created a subnet inside the VPC:

```hcl
resource "aws_subnet" "public" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.1.0/24"
  availability_zone = "ap-south-1a"
}
```

### Learnings

* Subnets divide VPC networks into smaller networks.
* `/24` subnet provides 256 IP addresses.
* Terraform automatically creates dependency relationships using resource references.

---

### 3. Internet Gateway

Created and attached Internet Gateway to VPC:

```hcl
resource "aws_internet_gateway" "igw" {
  vpc_id = aws_vpc.main.id
}
```

### Learnings

* Internet Gateway attaches to a VPC, not to a subnet.
* Provides internet connectivity for resources inside the VPC.
* Does not provide internet access by itself without routing.

---

### 4. Route Table

Created route table and default route:

```hcl
resource "aws_route_table" "public_rt" {
  vpc_id = aws_vpc.main.id

  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.igw.id
  }
}
```

### Learnings

* `0.0.0.0/0` represents all destinations.
* Route tables determine packet forwarding decisions.
* Internet-bound traffic is routed to the Internet Gateway.

---

### 5. Route Table Association

Associated subnet with route table:

```hcl
resource "aws_route_table_association" "public_assoc" {
  subnet_id      = aws_subnet.public.id
  route_table_id = aws_route_table.public_rt.id
}
```

### Learnings

* Route table associations bind a subnet to a routing policy.
* Without association, subnet cannot use custom routes.

---

### 6. Security Groups

Created SSH security group:

```hcl
resource "aws_security_group" "ssh_sg" {
  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
}
```

### Learnings

#### Ingress

Traffic entering the instance.

#### Egress

Traffic leaving the instance.

#### Security Best Practice

* Avoid `0.0.0.0/0` for SSH in production.
* Restrict access using VPN, Bastion Host, or corporate IP ranges.

---

### 7. EC2 Instance Provisioning

Created EC2 instance using Terraform:

```hcl
resource "aws_instance" "linux_server" {
  ami                         = data.aws_ami.amazon_linux.id
  instance_type               = "t3.micro"
  associate_public_ip_address = true
  key_name                    = "terraform-lab-key"
}
```

### Learnings

* Dynamic AMI lookup using Terraform data sources.
* Public IP required for direct SSH access.
* Key pairs are used for authentication.
* Security groups act as instance firewalls.

---

### 8. Terraform Dependency Graph

Learned how Terraform automatically determines resource creation order.

Example:

```hcl
subnet_id = aws_subnet.public.id
```

Terraform automatically understands dependencies:

VPC → Subnet → Route Table → Association → EC2

### 9. Real-World Troubleshooting

#### Issue

SSH connection failed:

```text
kex_exchange_identification
banner exchange
Connection timed out
```

#### Investigation Steps

1. Verified instance state
2. Verified public IP assignment
3. Verified security group rules
4. Verified route table configuration
5. Verified Internet Gateway attachment
6. Verified EC2 health checks
7. Verified cloud-init completion
8. Verified authorized_keys creation
9. Tested TCP connectivity using:

```powershell
Test-NetConnection <public-ip> -Port 22
```

#### Root Cause

Corporate VPN was interfering with SSH traffic.

#### Resolution

Disconnected VPN and SSH worked successfully.
